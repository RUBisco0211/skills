# 高效低碳燃气轮机试验数据智能化分析与应用平台

## 约 10 分钟视频讲解旁白与演示操作脚本

> 适用对象：技术交流、方案汇报、项目原型演示  
> 建议语速：每分钟 210～230 个汉字，关键数据处适当停顿  
> 建议画面：1920×1080，全屏浏览器，缩放比例 100%  
> 说明：当前 demo 为本地 Mock 数据驱动的界面原型，用于展示技术方案的目标形态与业务闭环，不等同于生产系统已经全部建成。

## 录制前准备

1. 在 `src` 目录执行 `npm run dev`，打开 `http://127.0.0.1:5173/`。
2. 刷新页面，使系统回到“门户总览”初始状态。
3. 收起浏览器侧边栏和收藏栏，尽量扩大业务界面区域。
4. 录制过程中鼠标移动要慢；进入新页面后停留 1～2 秒，再开始讲解。
5. “任务中心”的状态流转会改变当前页面内的 Mock 状态，刷新页面即可恢复；“报告中心”的编辑、下载按钮目前为展示占位，不建议点击。

技术方案采用纯本地私有化、分层解耦、组件化的一体化架构。基础设施层提供 GPU、CPU、存储与高速网络；算力与调度层通过 Kubernetes、Slurm 以及高性能模型推理服务，统一承载 AI 与 HPC 任务；数据与知识层负责多源接入、本体、知识图谱和向量检索；智能体平台层提供多模式路由、LightRAG、Skills、容器沙箱和复杂任务规划；最上层则面向科研人员提供查询、分析、仿真和报告应用。安全运维与标准规范纵向贯穿全平台，形成“六层两翼”的总体形态。

平台首先把异构资源统一纳管。当前演示视图映射了 6 个 GPU 节点、48 张卡，以及 CPU 计算资源，并统一呈现负载、温度、功率、队列和告警。向上层提供的不是孤立服务器，而是按项目、队列和优先级分配的标准算力服务。任务中心进一步把大模型推理、模型训练、CFD、MPI 并行和数据分析纳入同一套作业视图。长周期仿真任务支持检查点、失败重试和断点续算，使 AI 推理与工程计算可以共享资源，同时保持隔离、可控和可审计。

数据目录对应方案中的多源接入与语义治理能力。平台可统一接入试验台实时数据、关系数据库、时序数据库、文档与仿真结果，并对每个数据源记录同步方式、责任人、规模、质量评分和运行状态。接入后的数据会完成字段映射、单位换算、时间对齐、质量校验和血缘登记，再发布为可复用的数据集资产。这样，后续分析使用的是来源清楚、口径统一、处理过程可追溯的数据，而不是散落在各系统中的原始文件。

**旁白**

在统一数据之上，平台围绕部件、参数、工况、测点、试验和仿真对象建立领域本体与知识图谱。这里使用 LightRAG 的混合检索，将全文、向量和图谱关系结合起来。以“燃烧室出口温度受哪些因素影响”为例，系统不仅给出进气条件、当量比、燃烧效率、壁面散热和部件退化等结论，还同步展示证据来源、命中的实体、关系三元组与重排分数。回答因此能够追溯到具体报告和知识关系，降低单纯大模型问答中结论不可验证的问题。

## 04:00—05:50　智能分析：从自然语言到试验—仿真对标

**画面操作**

- 点击左侧“分析工作台”，停留在“自然语言查询”。
- 按顺序指向四步查询计划，以及三个试次的燃烧效率结果。
- 点击“试验对比分析”，展示三条出口温度曲线和“一致性好”的结论。
- 点击“CFD 与试验对比”，指向柱状对比、P2 出口曲线和右侧校准建议。
- 点击“历史趋势与异常”，指向趋势曲线和异常检测清单。

**旁白**

智能分析工作台把科研人员的自然语言问题转换为受约束的查询计划。这里的示例是对比 12 号试验台三个试次在设计点工况下的燃烧效率。系统先识别试验台、时间、工况和指标，再定位试次，随后完成字段、语法、逻辑、关联和权限五道校验，最后执行时间对齐、采样率统一与稳态段识别。三个试次的结果分别为 99.2%、98.9% 和 99.4%，差异小于 0.6%。

进一步切换到试验对比，可以查看多试次曲线叠加和差异结论；切换到 CFD 与试验对比，平台会把测点和场变量映射到统一语义下，计算误差并定位差异区域。当前示例平均相对误差为 3.4%，满足 5% 的校核阈值，同时给出湍流模型调整和出口回流区网格加密建议。历史趋势页面则把变化点、性能衰退和异常测点形成清单，实现从“看见数据”到“解释差异、给出建议”的提升。

## 05:50—07:10　仿真执行：状态机驱动的自动化流水线

**画面操作**

- 点击左侧“仿真工作台”。
- 在算例列表中点击“燃烧室 CH4/空气 稳态燃烧”。
- 鼠标沿“需求分析—几何处理—网格划分—求解设置—计算执行—后处理—试验校核—归档报告”从左向右移动。
- 指向 64% 进度、求解残差曲线和出口监测量。
- 点击列表最下方“燃烧室热态校核（试验对标）”，展示失败原因与“失败重试、人工接管”提示。
- 最后向下滚动，展示 MCP 工具注册表。

**旁白**

仿真工作台将过去依赖人工串联的几何、网格、设置、求解、后处理、试验校核和报告归档，组织为可中断、可恢复的流程状态机。每个状态都绑定明确的输入输出工件、MCP 动作与 HPC 作业模板，并通过版本快照保证断点续算后与原始执行保持等价。运行过程中，平台持续监测残差、出口温度、NOx 等关键量；当出现时间步长超出 CFL 限制等问题时，会记录失败原因，触发重试策略，也允许专家人工接管。底部工具注册表展示了 Salome、snappyHexMesh、OpenFOAM、Ansys Fluent、IDAES、ParaView、POD 加 Kriging 与 Slurm 等工具的统一接入方式。

## 07:10—08:45　智能体：一条自然语言指令贯通全流程

**画面操作**

- 点击左侧“智能体对话”。
- 点击预设问题“对比 12 号试验台设计点工况下三个试次的燃烧效率”。
- 再点击“发送”。
- 处理中保持画面不动；结果出现后，依次指向“路由：通用 Agent”、任务步骤、最终结论。
- 指向右侧工作目录中的 `data`、`scripts`、`results`、`reports`。
- 点击展开 `results`，展示 `comparison.xlsx`、`curves.png` 和 `summary.md`；再指向底部沙箱日志中的完成信息。

**旁白**

前面的数据、知识、分析和仿真能力，最终由科研智能体统一编排。科研人员只需要描述目标，不必逐个切换工具。平台先依据问题复杂度，在大模型直答、RAG 知识问答、通用 Agent 和 Hermes 闭环科研模式之间自动路由。当前请求被识别为多步骤分析任务，随后完成目标拆解，调用 LightRAG 定位试次与测点语义，在独立沙箱中执行数据获取、时间对齐和稳态段识别，再生成对比结论并回写知识图谱。

右侧工作目录保留了输入数据、执行脚本、结果文件和报告工件；底部终端则记录沙箱环境和执行轨迹。也就是说，智能体给出的不是一个无法复核的自然语言答案，而是一条包含数据来源、工具调用、过程文件和结果产物的可审计执行链。方案要求简单问答在 5 秒内响应、全文检索在 3 秒内响应，并通过本地模型、容器隔离和权限审计保证科研数据不出域。

## 09:20—10:05　收束：三类闭环与项目价值

**画面操作**

- 点击左侧“门户总览”。
- 滚动回页面顶部，停留在平台运行总览。

**旁白**

总体来看，这个平台形成了三条相互促进的闭环：数据经过治理进入知识体系，形成“数据到知识”的闭环；仿真结果与试验数据自动对标，校准建议再驱动下一轮计算，形成“仿真到分析”的闭环；智能体在执行中沉淀模板、技能与经验，形成“使用到进化”的闭环。最终实现算力统一供给、数据统一治理、知识统一组织、智能统一调度和应用统一门户，为燃气轮机试验效率提升、仿真可信度提升与科研知识长期沉淀提供完整技术底座。以上就是本次演示，谢谢观看。
