# WORKFLOW.md — 流程总纲

> 给人看，不进 AI 上下文。给 AI 的约束全在 `AGENTS.md`：本文件讲**怎么跑**，AGENTS.md 讲**不许做什么**。

## 1. 文件结构

```
project/
├── AGENTS.md              唯一常驻文件，<200 行
├── WORKFLOW.md            本文件
└── docs/
    ├── DECISIONS.md       决策索引
    ├── decisions/         决策正文，一条一个文件
    └── research/          调研文档
```

`AGENTS.md` 超过 200 行时，把最长的一节抽成 `docs/xxx.md`，并在其第 12 节登记触发场景。

## 2. 任务分档

| 档 | 判定 | 走哪些步骤 |
|---|---|---|
| **S** | 小 bugfix、改字段名、照已有模式加东西、明确的小重构 | 直接做 → 验收 → commit。不写文档 |
| **M** | 单模块内新功能、改动 ≤3 个文件、无数据模型变更 | design → 测试契约 → 实现 → 验收 → 沉淀 |
| **L** | one-way door（数据模型定型 / schema 变更 / 鉴权方案 / 服务边界）、横跨 >3 个模块、要拆给 subagent | grill → design → 测试契约 → 实现 → 验收 → 沉淀 |

拿不准时：**写不出 proposal，就说明还没想清楚，先 grill。**

## 3. 七阶段与关键节点

| # | 阶段 | AI 做什么 | 人做什么 | **放行判据** | 跳过代价 |
|---|---|---|---|---|---|
| 0 | 探查 | 读代码库、查已有模式 | 无（它不许问你） | — | — |
| 1 | **grill**（仅 L 档） | 每轮把整个 frontier 问完，每条附推荐答案 | 逐条回答，重点看**被否决项** | 你能想象出实现后的样子 | 方向错了几十个 commit 后才暴露 |
| 2 | **design** | ≤30 行，四字段 | 确认 | **你能复述 design 说了什么** | 越界代码、范围膨胀 |
| 3 | **测试契约** | 补断言 | 给测试名；**review 断言** | 「这些断言全绿 = 功能完成」成立 | 测试全绿但功能是错的 |
| 4 | 实现 | `/clear` 后按 task 逐个做 | 只在三种情况插手 | 每 task 可单独验证 | — |
| 5 | 验收 diff | — | 看三件事 | 三点都干净 | 技术债积累 |
| 6 | 沉淀 | 扫描会话输出增量 | 确认新增条目 | 每条禁令**具体可判定** | 同样的坑再踩 |
| 7 | commit + `/clear` | — | — | 完成标准四条全满足 | — |

- **阶段 4 只在三种情况插手**：① AI 主动问你；② 第三次纠正同一件事（此时该去改 `AGENTS.md` 第 5 节）；③ 一个 task 做完。原则是看结果不看过程。
- **阶段 5 验收三件事**：改了范围外的文件没 / 有没有"顺手重构" / 有没有吞异常、留 TODO。
- **阶段 6 沉淀**：AI 输出三块增量（新增 `Never do` 条目 / 新增决策文件与索引行 / 待办风险），你确认。

## 4. 六个 HITL 检查点

注意力放在「错误的发现距离最长」的地方：design 错了几十个 commit 后才暴露，代码错了几分钟测试就报。

| # | 检查点 | 看什么 | 时间 |
|---|---|---|---|
| 1 | grill | 被否决项写全没、out of scope 是不是你要的 | 15–30 min |
| 2 | design | 放哪层对不对、有没有偷偷加需求、边界漏什么 | 2–5 min |
| 3 | **断言** | 断言是否真表达了你要的行为 | 2–3 min |
| 4 | 实现中 | 只在上述三种情况插手 | 随机 |
| 5 | diff 验收 | 范围外改动 / 顺手重构 / 吞异常 | 5 min |
| 6 | 沉淀 | 新增禁令是否可判定 | 3 min |

失效模式：**橡皮图章**（自检：你能复述 design 说了什么吗）、介入太晚、介入太碎。

时间预算：L 档中型 feature 投入 30–50 分钟（grill 占大头），M 档约 15 分钟。

## 5. grill 判据

频率挂钩决策密度，不是 commit 频率。典型节奏：一个中型 feature grill 一次，之后 8–10 个 commit 都不再 grill。

- 该 grill：one-way door / 写不出 proposal / 横跨 >3 个模块 / 要拆给 subagent 之前 / 一个 feature 的开端。
- 不该 grill：小步实现、纯 bugfix、照已有模式加东西、明确的小重构。
- grill 对话是消耗品。要抢救的只有两样：**被否决的方案**（进 REJECTED）和**明确不做什么**（进 OUT OF SCOPE）。

## 6. 测试契约：谁写什么

让 AI 同时写测试和实现，测试会退化成「对实现的描述」而不是「对意图的约束」。判据：**如果一个测试能通过但代码是错的，它就没有价值。**

| 层 | 谁写 |
|---|---|
| 契约测试（接口行为、错误语义、数据模型约束） | **人主导** |
| 边界 / 异常测试（空值、超限、失败路径） | AI 写，人审 |
| 回归测试（锁住已修过的 bug） | AI 全权 |
| 实现细节测试（内部函数单测） | 少写或不写（一重构就全红） |

推荐模式：① 人写测试名（描述行为的句子）→ ② AI 填充断言和骨架 → ③ 人 review 断言 → ④ AI 写实现跑到通过。人的负担只有 ①③。

- **红步骤不能跳过**：第一次就全绿说明它在描述已有代码，重写。
- 粒度：跟着行为走，不跟着函数走。一个测试一个 reason to fail；测试名是完整句子。
- 边界：AI 穷举清单 → 你砍一半 → 保留的实现。必测四类：空/空集合、极大极小、并发与重复、外部依赖失败。
- 测试必须快且确定（慢/flaky 对 agent 循环是毒药）；测试名即上下文（`test_user_1` 会降低它后续实现质量）。

## 7. 调研文档

放 `docs/research/`，一个主题一个文件。

结构：**结论 → 依据 → 备选方案与取舍**。开头必须能直接读到结论，不写调研过程流水账。

- 调研文档是**参考资料，不是约束**。其中内容只有写进 `AGENTS.md` 第 5 节或 `docs/decisions/` 才对 AI 生效。
- 已调研过的主题在 `AGENTS.md` 第 12 节登记触发场景，否则 AI 不会主动读。
- 结论过期时新建文件或在顶部标注失效说明，不静默改写历史结论。

## 8. 任务清单（多会话时才建）

一次性 scratch，用完即删：

```
## 当前：<feature 名>
- [ ] T1 <做什么>　验证：<怎么确认它完成了>
- [ ] T2 <做什么>　验证：<>
## 已完成
- [x] T0 <>
## 本次明确不做
- <写在这里的，AI 就不会自作主张帮你做>
```

一个 task = 一个 commit = 一个干净会话；每个 task 必须能单独验证；状态只有 `[ ]` `[x]` `[!]` 三态，`[!]` 必须写清卡在哪。

## 9. 自检

- [ ] `AGENTS.md` 第 5 节最近一个月有新增条目吗？没有，说明这套体系已经死了。
- [ ] 你能复述上一次 design 说了什么吗？不能，说明你在橡皮图章。
- [ ] 上次 `/clear` 之前跑沉淀了吗？没跑，等于这个 feature 白干一半。
- [ ] `docs/DECISIONS.md` 索引和 `docs/decisions/` 下的文件对得上吗？

## 10. 启动清单

1. 填 `AGENTS.md` 第 1 节（5 行背景）和第 5 节 `Never do`（先写 5 条踩过的坑）。
2. 填第 3 节模式锚点（3–5 个真实文件路径）。
3. 第 2、4 节留空，等真有分层和外部依赖再补。
4. 拿一个 S 档任务试跑，确认第 5 节的禁令真的被遵守。

每次踩坑，花 30 秒在第 5 节加一行。
